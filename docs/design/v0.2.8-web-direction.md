# v0.2.8 `cmd/bestiary-web` — Visual Direction (RQ3 design study)

Status: **DRAFT — awaiting user sign-off at the RQ3 gate.** Nothing in `cmd/bestiary-web`
should be built until this doc is approved (PROPOSAL-5 §17.7, `bestiary-97yu0`).

Scope: this is a *design* artifact only — palette, type stack, layout grid, and component
sketches for the three MVP views (entity browser, entity detail, series/release explorer).
No code changes. Everything proposed here must be implementable in plain vendored CSS +
`html/template` + Datastar, with **zero CDN dependencies** (fonts and JS are `go:embed`
vendored, per F1/F4).

---

## 1. Reference study

### 1.1 Aesthetic refs (visual)

**sentry.artificialisabel.com** — a near-Earth-object tracking HUD console. Fetched and
inspected directly (raw HTML + inline `<style>`; a browser-UA-sniffing WebFetch pass got
only the page title, so this used a plain `curl` fetch instead — noted here since it's a
deviation from the "screenshot pass" instruction: no screenshot tool was available in this
session, so the direction below is built from the **actual shipped CSS**, which is a stronger
signal than a visual screenshot would be for palette/type/motif extraction, but the visual
composition (panel arrangement, motion) is inferred from the CSS rather than seen).

Extracted facts:
- **Palette** (dark-only site): `--bg:#05040A`, `--text:#f0b32a` (amber), `--amber-dim:#F26500`,
  `--amber-bright:#47FFA9` (this "bright" slot is actually a mint-green, not a brighter amber —
  a deliberate two-hue HUD scheme, amber for chrome + green for "live/active" state), plus
  `--blue:#5f7bff`, `--cyan:#39d6c8`, `--green:#54ff8a`, `--orange:#ff6a1f`, `--red:#ff3b2f` as a
  small status/badge set, and `--line:#7a5a14` for hairline borders.
- **Typography**: `Instrument Serif` (condensed, `scaleX(0.66)` squeeze) for big HUD titles,
  `Share Tech Mono` for the clock/numeric readout, `Saira Condensed`/`Helvetica Condensed` as
  the general UI mono-adjacent face. Both webfonts are Google Fonts — **OFL licensed**, so
  vendorable as `.woff2` under `go:embed` with no CDN call (F1 constraint).
- **Texture/motion**: a `.scan` repeating-linear-gradient scanline layer (`mix-blend-mode:
  multiply`, subtle `flick` keyframe), a `.vignette` radial darken at the edges, a `.noise`
  SVG-turbulence grain layer at very low opacity (`0.085`) with a slow jitter animation, and a
  `.bloom` backdrop-filter brightness/blur layer for a soft glow. `text-shadow: 0 0 6px
  currentColor` on badges/titles gives the "glowing phosphor" look cheaply.
- **Chrome**: rounded (`8px`) `1.5px` bordered panels with a corner radial-gradient "console
  glass" tint; pill-shaped `title-tag` badges with a glow; diamond-clipped range-slider thumbs.
  Layout is a CSS-grid console (`grid-template-areas: "mini main" "radar main" "feed main"`) —
  a fixed-viewport mission-control layout, not a scrolling document.
- **Verdict**: this is the strongest, most literal "phosphor/CRT" reference of the two, and it
  matches §17.7's brief almost verbatim ("Phosphor/CRT-inspired 2–3 hue theme … restrained
  scanline/grain overlay … glow"). It's the primary donor for the recommended direction below.

**fairtrade.peasantlabs.org** — "an open-source design system for agent products … dark-first,
square, neuroinclusive" (from its own meta description). Fetched via `curl` (WebFetch was
blocked with a 403 for this one — a UA or bot-check issue, not a dead site) and its built CSS
bundle (`/assets/index-*.css`, 361 KB) pulled directly.

Extracted facts:
- **Palette**: `--canvas:#070706` (dark) / `#fbfaf7` (light); a warm amber accent ramp
  (`--amber:#cba35c`/`#8a5f1f`, `--amber-fill:#b8841a`); an `ink` grayscale text ramp
  (`#e9e5db` → `#27241f` across 5 steps per mode); secondary hues `clay` (terracotta,
  `#c07f64`/`#974b32`) and `mauve` (`#9a8cae`/`#594e72`); a `danger` state distinct from the
  categorical clay. Corners are **square** (a deliberate "neuroinclusive" choice — no
  rounded-pill decoration competing for attention).
- **Typography**: `Atkinson Hyperlegible` + `Atkinson Hyperlegible Mono` — a font designed by
  the Braille Institute specifically for low-vision legibility. This is the opposite instinct
  from Sentry's stylized condensed HUD face: readability over vibe.
- **Verdict**: this is a *design-system* reference, not a HUD reference — it reads as
  "mid-century space-program print poster" (warm paper, square chrome, restrained amber) rather
  than "CRT console." It's the donor for the accessibility-first alternative direction
  (§4.2, "Space-Age Print") and for the **light-mode discipline**: bestiary-web needs a real
  light theme too (project's dark/light discipline, §17.7), and Sentry's site has none — a
  from-scratch light mode "reads" better as a print-poster register than as a "daylight CRT,"
  which doesn't really exist as a visual metaphor.

### 1.2 Information-density refs — whichllm.app / whichllm.io (VERIFIED)

Both were flagged **UNVERIFIED** in prior research (PROPOSAL-5 §17.7 caveat: "the whichllm
visual reference is inferred, not directly observed"). Both are confirmed **live** this pass:

- **whichllm.app** — a hardware-matching wizard: Use Case / OS / RAM / VRAM inputs plus a
  three-tier quality slider (Max Quality / Balanced / Max Context), then a personalized model
  recommendation. Minimalist, form-first, low information density. Not directly relevant to
  bestiary's browse-and-compare MVP (this is closer to the DEFERRED v0.2.9 VRAM calculator).
- **whichllm.io** — a dense, scrollable comparison table over "3k+ models" sourced from
  **models.dev** (the same upstream bestiary ingests). Columns: name, provider, capabilities,
  context window, input/output cost per 1M tokens. Sortable by name/provider/family/cost/
  context/release date. Capability-based filter chips (long context, reasoning, tool calling,
  vision) plus media-type tabs (text/image/audio/video). A `⌘K` command palette for quick
  navigation. This is the **direct density lesson** for the entity browser: sortable dense
  table + chip filters + a command palette, not a card grid.

This confirms the whichllm.io density model is real and reusable pattern-for-pattern: the
entity browser's filter row (family/creator/provider/region/modality per §17.5) maps directly
onto whichllm.io's chip-filter + sortable-column pattern, and a `⌘K`-style command palette is a
cheap, high-value addition to scope alongside it (server-rendered options list + Datastar
`data-on:keydown` binding — no client router required).

## 2. Recommended direction: **Phosphor Terminal**

Primary recommendation. Directly executes §17.7's brief ("Phosphor/CRT-inspired 2–3 hue theme
… monospace/slab display face … restrained scanline/grain … View-Transition fragment reveal")
using Sentry's verified CSS as the literal donor, while obeying the one hard override in the
same spec: **the data grid stays high-contrast and scannable — retro skin lives on the chrome
(borders/headers/badges), never on the dense table body.** Concretely: table body text is a
near-neutral ivory/charcoal (WCAG-comfortable for extended scanning of 958 rows), while nav,
panel borders, section headers, and status badges carry the amber glow/scanline treatment.

### 2.1 Palette (2-hue core + status set, both modes)

| Token | Dark | Light | Use |
|---|---|---|---|
| `--bg` | `#0a0908` | `#f7f3e8` | page canvas |
| `--surface` | `#141210` | `#ffffff` | table/panel background |
| `--text` | `#ece6d8` | `#1c1810` | body/table text (high-contrast, NOT amber) |
| `--text-muted` | `#9b9285` | `#6b6152` | secondary/meta text |
| `--accent` (amber) | `#f0b32a` | `#a8660a` | chrome: headers, active nav, focus ring, glow |
| `--accent-dim` | `#7a5a14` | `#d9c9a0` | hairline borders, inactive dividers |
| `--accent-bright` (phosphor green) | `#54ff8a` | `#0f7a4a` | "live/attested" badges (e.g. multi-source entity) |
| `--info` (cyan) | `#39d6c8` | `#0d7d76` | modality/capability badges |
| `--warn` (orange) | `#ff6a1f` | `#b5471f` | partial-VRAM-estimate / deferred-data badges |
| `--danger` (red) | `#ff3b2f` | `#a12318` | parse-failure / unlinked badges (admin-facing only) |
| `--border` | `#3a2c0a` | `#d9c9a0` | panel/table borders |

Both are driven by `prefers-color-scheme` with a manual `data-theme` override (matches the
project's existing dark/light discipline). This is a **2-hue core** (amber + phosphor-green)
plus a **4-color status set** (info/warn/danger/bright) — status colors are reserved for
state, never reused as a 5th/6th categorical hue (dataviz skill: "status colors are reserved
… never reused for 'series 4'").

Where the doc later needs a *sequential* ramp (VRAM-bar fill, benchmark-score bars) it is a
single-hue amber ramp (light→dark), not a second categorical hue — per the dataviz skill's
"sequential = one hue" rule. Any such bar/meter component should be validated with
`scripts/validate_palette.js` at implementation time against both surfaces before shipping.

### 2.2 Type stack (vendored, no CDN)

| Role | Face | Fallback stack | Notes |
|---|---|---|---|
| Display (hero titles, section headers) | `Saira Condensed` 600/700 | `system-ui, sans-serif` | vendor `.woff2` subset (Latin only) via `go:embed`; OFL licensed |
| Chrome mono (nav, badges, filter labels) | `Share Tech Mono` | `ui-monospace, Menlo, monospace` | same OFL family Sentry uses for its clock readout — cheap "terminal" signal |
| Body / dense table | **system stack only** | `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` | deliberately NOT a vendored display face — the "grid stays scannable" rule; system fonts render sharpest at small table sizes and need zero vendoring |
| Tabular numerals (price/VRAM/context columns) | table stack + `font-variant-numeric: tabular-nums` | — | keeps numeric columns vertically aligned without a monospace font |

Two `.woff2` files to vendor (Saira Condensed, Share Tech Mono — both SIL OFL 1.1), pinned by
version with a `SNAPSHOT`-style provenance note next to them, exactly like the `datastar.js`
vendoring discipline in §17.2.

### 2.3 Texture (restrained, per §17.7 — "restrained scanline/grain… single CSS gradient")

One scanline layer only (`repeating-linear-gradient`, `mix-blend-mode: multiply`, ~8% opacity,
`prefers-reduced-motion` respected — no animation when set), applied to the page chrome
(`body::after`, `pointer-events: none`), **not** layered again over the table. No vignette, no
noise-turbulence, no bloom/backdrop-filter — Sentry stacks four such layers for a mission-control
console that never needs to be read as dense tabular data; bestiary-web does, so it takes the
single cheapest layer and stops. A `::view-transition` fragment-reveal (already planned per
§17.1/17.3) supplies the "alive" feeling instead of the extra texture layers.

### 2.4 Layout grid

- **Shell**: fixed top chrome bar (wordmark + `⌘K`-style command trigger + theme toggle) +
  a collapsible left filter rail (family/creator/provider/region/modality chips, matching
  whichllm.io's chip pattern) + a scrolling content area. Unlike Sentry's fixed-viewport
  console grid, bestiary-web's content **scrolls** — it's a hypermedia document set (§17.4
  routes are independently linkable pages), not a single-page console.
- **Breakpoint**: single collapse at ~768px — filter rail becomes a top drawer, matching the
  project's existing mobile-first console pattern from the Sentry reference (adapted, not
  copied — no fixed-viewport lock).
- **Grid unit**: 8px base spacing scale (4/8/16/24/32), square corners on data chrome
  (border-radius 0–2px) except small pill badges (radius 999px) for capability/status tags —
  a restrained middle ground between Sentry's fully-rounded panels and fairtrade's fully-square
  system.

## 3. Constraints honored

- Plain vendored CSS, no framework (Tailwind, Bootstrap, etc.) — confirmed against fairtrade's
  React+Tailwind stack, which is explicitly the pattern **not** followed here.
- `html/template` + Datastar SSE only, no client router/build step (§17.1).
- Two `.woff2` webfonts vendored under `go:embed`, version-pinned with a `SNAPSHOT` provenance
  note (mirrors the `datastar.js` vendoring discipline, §17.2) — **no Google Fonts CDN call**.
- Data grid stays high-contrast/scannable; retro skin confined to chrome — the one explicit
  override in §17.7 against a literal Sentry copy.
- Any bar/meter component (VRAM fill, benchmark score) uses a single-hue sequential ramp,
  validated with the dataviz skill's `validate_palette.js` before shipping (deferred to the
  implementation slice — this doc fixes the hex values, not the validation run).

## 4. Alternative directions considered

| Direction | Look & feel | Palette anchor | Pros | Cons | Fit vs §17.7 |
|---|---|---|---|---|---|
| **Phosphor Terminal** (recommended) | amber CRT-HUD chrome over a neutral scannable data grid | Sentry (verified, literal donor) | Directly matches spec wording; real CSS to copy faithfully; cheap (1 scanline layer, 2 vendored fonts); dense-table-friendly | Amber-on-black skews "ops console," slightly colder than a consumer product | Exact match |
| **Space-Age Print** | warm paper / charcoal, square corners, Atkinson Hyperlegible, mid-century space-program poster restraint, no scanline/glow at all | fairtrade (verified) | Best-in-class accessibility (Hyperlegible is purpose-built for low vision); calmer, ages well; simplest to vendor (fewer effect layers) | Reads as "design system," not "retrofuturism" — misses the CRT/phosphor brief almost entirely; would need a written justification for why it satisfies F4 | Weak — closer to a rejection of the retrofuturism brief than a variant of it |
| **Cassette-Futurism** | warm analog: tape-deck oranges/browns, embossed/inset borders, VU-meter-style gauges for VRAM (needle + arc, not a bar) | Neither ref directly (a third register, extrapolated) | Most distinctive/memorable; VU-meter VRAM gauge is a fun, on-brief motif | No verified reference site to anchor exact hex/type choices (higher design risk); needle gauges are harder to keep "high-contrast and scannable" at dense-table scale (dataviz anti-pattern risk: gauges read one value at a time, don't scale to 958 rows); heavier chrome (embossing, insets) fights the "restrained" instruction in §17.7 | Partial — same phosphor spirit but higher execution risk with no verified donor |

**Recommendation: Phosphor Terminal.** It is the only option with a *verified, literal* CSS
donor that matches §17.7's brief word-for-word ("Phosphor/CRT-inspired," "monospace/slab
display," "restrained scanline/grain," "glow"), it is the cheapest to vendor (one texture
layer, two OFL webfonts, a 2-hue-plus-status palette), and its "retro chrome / neutral grid"
split directly resolves the one tension in the spec (retrofuturism aesthetic vs. a 958-row
scannable table) without inventing a new rule.
